# Phase 3: A40 Baseline Benchmark

Date drafted: 2026-06-22

## Overview

Run a real one-GPU A40 baseline benchmark with the upstream `parameter-golf/train_gpt.py` script.

Phase 2 proved that the baseline script can run end-to-end and report `val_bpb`. Phase 3 should produce a useful A40 reference point for speed, memory, artifact size, and 10-minute-style BPB before qMLP changes are introduced.

## Why This Matters

The qMLP idea needs a fair baseline. Without an A40 baseline run using the same data, environment, tokenizer, model, and logging path, later qMLP results cannot be interpreted.

This phase moves us closer to the qMLP decision by establishing:

- how fast the simple baseline trains on OSU A40;
- how much fixed overhead comes from compile, final validation, and compression;
- what `val_bpb` the simple baseline reaches under a 600-second training cap;
- what resource request is practical for repeated A40 experiments.

## Resource Requests

### Data Completion

Download the default `sp1024` train cache through a CPU Slurm job:

```text
partition=share
time=01:00:00
nodes=1
ntasks=1
cpus-per-task=2
mem=8G
```

Command:

```bash
python data/cached_challenge_fineweb.py --variant sp1024 --train-shards 80
```

This should fill out `fineweb_train_000000.bin` through `fineweb_train_000079.bin` plus the fixed validation shard and tokenizer files.

### A40 Benchmark

Use the earliest accessible A40 partition that passes `srun --test-only`.

Initial request:

```text
partition=share
constraint=a40
gres=gpu:1
time=00:25:00
nodes=1
ntasks=1
cpus-per-task=2
mem=24G
```

Rationale:

- `share/a40` was the earliest usable A40 target in Phase 2.
- 25 minutes leaves room for compile, 600 seconds of training, final validation, quantization, and roundtrip validation.
- 4 CPUs kept the Phase 2 request small enough to start despite account pressure.
- Live scheduler checks later showed that the account was blocked by `QOSGrpCpuLimit`, so the submitted benchmark was reduced to 2 CPUs and 24G RAM. That is still reasonable for this single-process, no-worker baseline and avoids waiting behind an unnecessary CPU request.

## Failure and Fallback Rules

- If the 80-shard data job fails from download/rate limits, preserve the partial shard count and retry once with the same command before changing scope.
- If account/QOS pressure blocks A40 for a long time, keep one small job queued and do not submit duplicates.
- If the default batch OOMs, rerun once with `TRAIN_BATCH_TOKENS=262144` and `VAL_BATCH_SIZE=262144`, and record that the full default batch did not fit on the chosen A40 target.
- If the job times out after successful training but before final roundtrip metrics, increase Slurm walltime without increasing `MAX_WALLCLOCK_SECONDS`.
- If bf16 or flash attention fails, preserve the exact error and do not switch to a different attention path in this phase.
- Do not use H100/H200 for Phase 3.

New facts:

- The full default `sp1024` 80-shard cache downloads quickly enough from a CPU Slurm job when `HF_HOME` is on shared storage.
- For current `eecs`/`normal` QOS pressure, reducing CPU and memory requests materially improves start likelihood.
- The useful A40 benchmark request for this baseline is `share`, `a40`, one GPU, 2 CPUs, 24G RAM, 25 minutes.
- The simple baseline on one A40 completes about 379 full default-batch training steps in a 600-second training cap.
- The measured training throughput is about `1.587s/step` for `TRAIN_BATCH_TOKENS=524288`, or about `330k tokens/s` globally.
- The total Slurm elapsed time was `14:26`, so compile/warmup/final validation/compression overhead outside measured training was roughly `4:24`.
- Final roundtrip BPB is meaningfully worse than pre-quantization BPB in this run: `1.58081095` versus `1.5584`.
- The artifact is comfortably below the 16MB cap at about `9.31MB` total int8+zlib submission size.

- Continue to Phase 4: Quaternion MLP Correctness.

- Phase 4 should use the Phase 3 baseline facts as the comparison reference: `17,059,912` params, `1.587s/step`, `379` steps in 600 seconds, final roundtrip `val_bpb:1.58081095`.
