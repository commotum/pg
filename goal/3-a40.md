# Phase 3: A40 Baseline Benchmark

Date drafted: 2026-06-22

## Overview

Run a real one-GPU A40 baseline benchmark with the upstream `parameter-golf/train_gpt.py` script.

Phase 2 proved that the baseline script can run end-to-end and report `val_bpb`. Phase 3 should produce a useful A40 reference point for speed, memory, artifact size, and 10-minute-style BPB before qMLP changes are introduced.

## Why This Matters

The qMLP idea needs a fair baseline. Without an A40 baseline run using the same data, environment, tokenizer, model, and logging path, later qMLP results cannot be interpreted.

This phase moves us closer to the qMLP decision by establishing:

- how fast the simple baseline trains on OSU A40;
- how much fixed overhead comes from compile, final validation, and compression;
- what `val_bpb` the simple baseline reaches under a 600-second training cap;
- what resource request is practical for repeated A40 experiments.

## Resource Requests

### Data Completion

Download the default `sp1024` train cache through a CPU Slurm job:

```text
partition=share
time=01:00:00
nodes=1
ntasks=1
cpus-per-task=2
mem=8G
```

Command:

```bash
python data/cached_challenge_fineweb.py --variant sp1024 --train-shards 80
```

This should fill out `fineweb_train_000000.bin` through `fineweb_train_000079.bin` plus the fixed validation shard and tokenizer files.

### A40 Benchmark

Use the earliest accessible A40 partition that passes `srun --test-only`.

Initial request:

```text
partition=share
constraint=a40
gres=gpu:1
time=00:25:00
nodes=1
ntasks=1
cpus-per-task=4
mem=64G
```

Rationale:

- `share/a40` was the earliest usable A40 target in Phase 2.
- 25 minutes leaves room for compile, 600 seconds of training, final validation, quantization, and roundtrip validation.
- 4 CPUs kept the Phase 2 request small enough to start despite account pressure.
- 64G RAM gives more headroom for the default batch and validation path without using a large CPU count.

## Benchmark Configuration

Use the upstream simple baseline, not a record script.

```text
RUN_ID=baseline_a40_10m_seed42_job<job-id>
DATA_PATH=/nfs/hpc/share/peterj29/pg/src/pg/parameter-golf/data/datasets/fineweb10B_sp1024
TOKENIZER_PATH=/nfs/hpc/share/peterj29/pg/src/pg/parameter-golf/data/tokenizers/fineweb_1024_bpe.model
VOCAB_SIZE=1024
SEED=42
ITERATIONS=20000
WARMUP_STEPS=20
TRAIN_LOG_EVERY=20
VAL_LOSS_EVERY=0
TRAIN_BATCH_TOKENS=524288
VAL_BATCH_SIZE=524288

```

This is intended to measure the simple default baseline under a 600-second training cap. It is not yet an optimized A40 run.

## Implementation Steps

1. Run a CPU data-completion job for `sp1024 --train-shards 80`.

2. Verify data completeness:

```bash
find data/datasets/fineweb10B_sp1024 -name 'fineweb_train_*.bin' | wc -l
find data/datasets/fineweb10B_sp1024 -name 'fineweb_val_*.bin' | wc -l
```

Expected:

```text
train shards: 80
val shards: 1
```

3. Run fresh scheduler fit checks for:

```bash
srun --test-only -p share --constraint=a40 --gres=gpu:1 \
  --time=00:25:00 --cpus-per-task=4 --mem=64G true

srun --test-only -p ampere --constraint=a40 --gres=gpu:1 \
  --time=00:25:00 --cpus-per-task=4 --mem=64G true

srun --test-only -p preempt --constraint=a40 --gres=gpu:1 \
  --time=00:25:00 --cpus-per-task=4 --mem=64G true
```

4. Submit the A40 benchmark job.

5. Preserve artifacts under:

```text
/nfs/hpc/share/peterj29/pg/runs/phase3-a40/<job-id>/
```

6. Extract and record:

- Slurm state and exit code;
- node and GPU model;
- driver and CUDA versions;
- loaded modules;
- PyTorch version;
- command and environment variables;
- train shard count;
- validation token count;
- `model_params`;
- warmup duration visible from logs;
- steps completed before wallclock stop;
- train-time milliseconds;
- step average;
- final `val_loss`;
- final `val_bpb`;
- peak memory allocated/reserved;
- fp32 model size;
- int8+zlib artifact size;
- total int8+zlib submission size;
- roundtrip `val_loss` and `val_bpb`;
- roundtrip validation time.

## Completion Requirements

This phase is complete when:

- The `sp1024` cache has 80 train shards and one validation shard.
- An A40 baseline benchmark job reaches state `COMPLETED`.
- Job exit code is `0:0`.
- The log shows the run used `MAX_WALLCLOCK_SECONDS=600`.
- The log shows the number of training steps completed.
- The log includes final `val_loss` and `val_bpb`.
- The log includes int8+zlib roundtrip metrics.
- `final_model.int8.ptz` exists in the preserved job directory.
- Metrics are recorded in this phase file.
- The Phase 4 decision says whether qMLP correctness work can begin.

## Failure and Fallback Rules

- If the 80-shard data job fails from download/rate limits, preserve the partial shard count and retry once with the same command before changing scope.
- If account/QOS pressure blocks A40 for a long time, keep one small job queued and do not submit duplicates.
- If the default batch OOMs, rerun once with `TRAIN_BATCH_TOKENS=262144` and `VAL_BATCH_SIZE=262144`, and record that the full default batch did not fit on the chosen A40 target.
- If the job times out after successful training but before final roundtrip metrics, increase Slurm walltime without increasing `MAX_WALLCLOCK_SECONDS`.
- If bf16 or flash attention fails, preserve the exact error and do not switch to a different attention path in this phase.
- Do not use H100/H200 for Phase 3.
