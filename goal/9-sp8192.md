# Phase 9: sp8192 Vocabulary Probe

Date drafted: 2026-06-22

## Overview

Test whether the validated matrix qMLP parameter savings can support an `sp8192` tokenizer and improve BPB beyond the replicated `sp4096` result.

Phase 8 made `sp4096` qMLP the current best simple candidate:

```text
dense_sp1024_phase3_roundtrip_val_bpb=1.58081095
qmlp_sp4096_seed42_roundtrip_val_bpb=1.55222627
qmlp_sp4096_seed0_roundtrip_val_bpb=1.54759284
qmlp_sp4096_seed1_roundtrip_val_bpb=1.55872027
qmlp_sp4096_mean_roundtrip_val_bpb_seed42_0_1=1.55284646
```

This phase asks whether one more vocabulary step buys more BPB without blowing up wallclock throughput or artifact size.

## Current Facts

- The repo's relevant record track is `track_10min_16mb`, and `goal/3-a40.md` records the cap as 16 MB.
- `sp4096` qMLP total int8+zlib submission sizes landed near 10 MB, not near 16 MB:

```text
seed42_total_int8_zlib_submission=9982431 bytes
seed0_total_int8_zlib_submission=9999583 bytes
seed1_total_int8_zlib_submission=9993892 bytes
```

- `sp8192` adds `4096 * 512 = 2,097,152` tied embedding parameters relative to `sp4096`.
- Predicted qMLP `sp8192` parameter count is:

```text
qmlp_sp1024_params=9982024
extra_vocab_params=(8192 - 1024) * 512 = 3670016
predicted_qmlp_sp8192_params=13652040
```

- This remains below dense `sp1024` `17059912` parameters by `3407872`.
- Artifact size is plausible under 16 MB, but must be measured because trained embedding rows may compress poorly.

## Implementation Steps

1. Add a local `sp8192` tokenizer config.

Use a config that defines only:

```text
name=sp_bpe_8192
dataset_suffix=sp8192
vocab_size=8192
```

2. Run bounded CPU data export.

Reuse the Phase 7 exporter path and selected-docs cache:

```text
output_root=/nfs/hpc/share/peterj29/pg/data-exports/sp8192-80
tokenizer_train_docs=500000
max_train_shards=80
skip_byte=true
```

Keep this on Slurm CPU nodes. Do not tokenize on a submit node.

3. Validate the export.

Record:

- manifest path;
- tokenizer name and vocab size;
- tokenizer model/vocab file sizes;
- train shard count;
- validation shard count;
- train token count;
- validation token count.

4. Run `sp8192` qMLP smoke on one A40.

Use:

```text
QUAT_MLP=1
QUAT_MLP_IMPL=matrix
VOCAB_SIZE=8192
ITERATIONS=2
WARMUP_STEPS=1
TRAIN_BATCH_TOKENS=65536
VAL_BATCH_SIZE=65536
MAX_WALLCLOCK_SECONDS=0
```

The smoke must record parameter count, roundtrip BPB, step speed, GPU memory, and total int8+zlib submission size.

5. Apply the artifact-size gate.

If smoke total int8+zlib submission size is at or above 16 MB, stop this phase and do not run the 10-minute benchmark.

If smoke is under 16 MB with reasonable headroom, run one 10-minute A40 benchmark with the Phase 7/8 benchmark shape:

```text
SEED=42
ITERATIONS=20000
WARMUP_STEPS=20
TRAIN_BATCH_TOKENS=524288
VAL_BATCH_SIZE=524288
MAX_WALLCLOCK_SECONDS=600
```

6. Compare against `sp4096`.

Compare:

- benchmark roundtrip BPB against `sp4096` seed `42`;
- benchmark roundtrip BPB against the three-run `sp4096` mean;
- steps and `step_avg` against `sp4096`;
- total int8+zlib submission size against 16 MB.

## Completion Requirements

This phase is complete when:

- the `sp8192` data export reaches terminal state, or the export blocker is captured;
- if export succeeds, a smoke job reaches terminal state and records artifact size;
- a benchmark is run only if the smoke artifact-size gate passes;
- `goal/0-plan.md`, this file, and stale prior docs are updated with the result;
- the decision says whether to seed-replicate `sp8192`, stay with `sp4096`, try width/depth, or move to H100/H200 confirmation.

## Failure and Fallback Rules

- If A40 scheduling is blocked, do not change model settings just to get a run; wait or record a partial result.
- If data export is slow but progressing, let it complete within the four-hour CPU walltime.
- If data export fails due tokenizer memory or runtime, retry once with fewer tokenizer training docs before abandoning.
- If smoke artifact size is over 16 MB, stop `sp8192`; do not benchmark an ineligible candidate.
- If `sp8192` benchmark improves BPB but is close to 16 MB, seed-replicate before H100/H200.
- If `sp8192` is worse than `sp4096`, keep `sp4096` as the simple candidate and consider width/depth or stronger-stack integration.
