# Phase 11: sp16384 Initial qMLP Probe

Date drafted: 2026-06-22

## Overview

Probe whether a final simple-stack vocabulary expansion from `sp8192` to `sp16384` improves matrix qMLP under the 16 MB artifact cap.

This is the last planned simple-stack vocabulary probe before moving to dense budget controls and record-stack work. It is a probe, not a new open-ended vocabulary ladder.

## Why This Matters

Phase 10 showed `sp8192` is seed-robust:

```text
qmlp_sp8192_seed42_roundtrip_val_bpb=1.52530269
qmlp_sp8192_seed0_roundtrip_val_bpb=1.52474158
qmlp_sp8192_seed1_roundtrip_val_bpb=1.52563039
qmlp_sp8192_mean_roundtrip_val_bpb_seed42_0_1=1.52522489
```

The revised project question is not whether qMLP beats underfilled dense `sp1024`; it is whether qMLP helps produce a best-under-16MB configuration against dense and record-stack controls.

`sp16384` tests whether the simple qMLP vocabulary reinvestment still has useful headroom before record-stack work begins.

## Current Facts

- Dense `sp1024` Phase 3 roundtrip BPB: `1.58081095`.
- Replicated qMLP `sp4096` mean roundtrip BPB: `1.55284646`.
- Replicated qMLP `sp8192` mean roundtrip BPB: `1.52522489`.
- Phase 9 `sp8192` benchmark total int8+zlib submission size: `11602814` bytes.
- Phase 10 `sp8192` seed total int8+zlib submission sizes: `11596618` and `11595190` bytes.
- The relevant local record track is `track_10min_16mb`.

Predicted simple qMLP `sp16384` parameter count:

```text
qmlp_sp1024_params=9982024
extra_vocab_params=(16384 - 1024) * 512 = 7864320
predicted_qmlp_sp16384_params=17846344
dense_sp1024_params=17059912
```

This exceeds dense `sp1024` by about `786432` parameters, so the justification is artifact-capped BPB, not raw parameter savings.

## Implementation Steps

1. Add a local `sp16384` tokenizer config.

Use:

```text
name=sp_bpe_16384
dataset_suffix=sp16384
vocab_size=16384
```

2. Export bounded data on a CPU Slurm job.

Use:

```text
output_root=/nfs/hpc/share/peterj29/pg/data-exports/sp16384-80
tokenizer_train_docs=500000
max_train_shards=80
skip_byte=true
```

3. Validate the export.

Record:

- manifest path;
- tokenizer name and vocab size;
- tokenizer model/vocab file sizes;
- train shard count;
- validation shard count;
- train token count;
- validation token count.

4. Run an A40 smoke/package-size gate.

Use:

```text
QUAT_MLP=1
QUAT_MLP_IMPL=matrix
VOCAB_SIZE=16384
ITERATIONS=2
WARMUP_STEPS=1
TRAIN_BATCH_TOKENS=65536
VAL_BATCH_SIZE=65536
MAX_WALLCLOCK_SECONDS=0
```

The smoke must record parameter count, BPB, step speed, GPU memory, int8+zlib artifact size, and total int8+zlib submission size.

The smoke artifact is only a gate. It is not a reliable final package-size prediction, because trained 10-minute artifacts can compress much worse than two-step smoke artifacts.

5. If the smoke gate passes, run a parallel seed batch.

Start with:

```text
SEED_VALUE=42
SEED_VALUE=0
SEED_VALUE=1
```

Submit all three A40 benchmark seeds concurrently if scheduler/account limits allow it. If not, run the maximum schedulable subset and document the fallback.

Use the Phase 9/10 benchmark shape:

```text
ITERATIONS=20000
WARMUP_STEPS=20
TRAIN_BATCH_TOKENS=524288
VAL_BATCH_SIZE=524288
MAX_WALLCLOCK_SECONDS=600
```

6. Compare against `sp8192`.

Compare:

- seed and mean roundtrip BPB against replicated `sp8192`;
- steps and `step_avg`;
- total int8+zlib submission size against the 16 MB cap;
- memory and any stability issues.

## Completion Requirements

This phase is complete when:

- the `sp16384` export reaches terminal state, or the export blocker is captured;
- if export succeeds, a smoke/package-size job reaches terminal state;
- no benchmark is submitted if the smoke package size is at or above 16 MB;
- if the smoke gate passes, the initial parallel benchmark seed batch reaches terminal state;
- each completed run has log and artifact facts recorded;
- `goal/0-plan.md` and this file are updated;
- the next decision is explicit: stop simple vocab expansion, run more `sp16384` seeds, use `sp16384`, or use `sp8192` as the simple-stack qMLP candidate.

## Failure and Fallback Rules

- If export fails due tokenizer memory or runtime, retry once with fewer tokenizer training docs before abandoning.
- If A40 scheduling cannot run three seeds in parallel, run the maximum schedulable subset and document the blocker.
- If smoke package size is at or above 16 MB, stop `sp16384` without benchmarking.
- If final benchmark package size exceeds 16 MB, mark `sp16384` ineligible even if BPB improves.
- If `sp16384` is clearly worse than `sp8192`, stop simple-stack vocab expansion and move to record-stack work.
- If `sp16384` improves or is close to `sp8192`, consider Phase 12 for additional seeds only if the initial seed batch is not decisive.
- Do not continue to `sp32768` or incremental vocab search unless the result creates a specific new compression or package-budget question.
