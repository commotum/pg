# Phase 15: Record qMLP sp16384

Date drafted: 2026-06-22

## Overview

Run the fixed record-stack qMLP `sp16384` reinvestment benchmark on A40 after the `sp8192` record controls exist.

The benchmark set for the resumed goal is:

```text
Phase 13: dense record sp8192
Phase 14: qMLP record sp8192
Phase 15: qMLP record sp16384
```

This phase deliberately does not search for the largest possible vocabulary. The package-frontier route remains documented in `goal/15-vocab-max.md` and `goal/15-package-frontier-results.md`, but it is deferred until the fixed comparison says larger vocab is worth pursuing.

## Why This Matters

The simple stack showed `sp16384` fit under the package cap but lost to `sp8192`. The record stack may respond differently because the architecture, tokenizer format, CaseOps preprocessing, compression path, and qMLP parameter savings are different.

This phase answers the immediate reinvestment question:

```text
Does record qMLP sp16384 improve over record qMLP sp8192 enough to overcome the qMLP tax versus dense record sp8192?
```

## Dependencies

- Phase 13 must leave a usable dense record `sp8192` A40 control.
- Phase 14 must leave a usable qMLP record `sp8192` A40 tax measurement.
- CaseOps `VOCAB_SIZE=16384` tokenizer/data must be built or staged for the 04-23 record path.
- The A40 SDPA fallback policy must match Phases 13 and 14 unless a change is mechanically required and documented.

## Implementation Steps

1. Confirm controls.

Record the Phase 13 and Phase 14 control summaries:

- seeds;
- BPB;
- steps and ms/step;
- package sizes;
- memory;
- hardware;
- A40 compatibility switches.

2. Build or stage CaseOps `sp16384`.

Use the existing Phase 15 scripts where appropriate:

```text
VOCAB_SIZE=16384 sbatch goal/15-caseops-vocab.sbatch
```

Do not use the simple-stack `sp16384` shards directly. The record stack needs CaseOps tokenizer/data and validation byte sidecars.

3. Run qMLP `sp16384` package/path smoke.

Use:

```text
VOCAB_SIZE=16384 sbatch goal/15-qmlp-package-smoke.sbatch
```

This smoke is a guard for path wiring, memory, and package-size surprises. It is not a BPB result.

4. Run A40 qMLP `sp16384` benchmarks.

Use the same seed policy as Phase 13 and Phase 14. Parallelize independent seeds when scheduler/account limits allow.

Keep fixed:

- record stack target;
- A40 fallback policy;
- optimizer policy;
- TTT policy;
- compression/package path;
- wallclock;
- batch settings unless a mechanical fit issue is documented.

Change only:

- `VOCAB_SIZE=16384`;
- tokenizer/data paths;
- `QUAT_MLP=1`;
- `QUAT_MLP_IMPL=matrix`.

5. Compare.

Compare `sp16384` qMLP against:

- dense record `sp8192`;
- qMLP record `sp8192`.

## Completion Requirements

This phase is complete when:

- CaseOps `sp16384` tokenizer/data prerequisites are present or a blocker is documented;
- a qMLP `sp16384` package/path smoke reaches terminal state;
- at least one qMLP `sp16384` A40 benchmark reaches terminal state if the smoke passes;
- job IDs, seeds, BPB, steps, ms/step, package size, memory, hardware, and command/config are recorded;
- the decision says whether larger-vocab frontier probing should reopen.

## Failure and Fallback Rules

- If `sp16384` package/path smoke is unexpectedly near or above 16 MB, stop and reassess before full benchmarks.
- If `sp16384` loses to qMLP `sp8192`, do not continue larger-vocab probing without a new reason.
- If `sp16384` beats qMLP `sp8192` but not dense record `sp8192`, record vocab reinvestment as helpful but not enough.
- If `sp16384` beats dense record `sp8192`, promote it to the Phase 16 A40 head-to-head contender.
